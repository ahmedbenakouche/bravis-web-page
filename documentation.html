01Installation et prérequisInstallation & requirements

BRAVIS n’est pas encore publié comme extension officielle de 3D Slicer : le projet est encore en développement, donc il n’apparaît pas dans l’Extensions Manager. Pour l’instant, on l’installe à la main (dossier du dépôt + chemin de module), comme ci-dessous. BRAVIS is not published yet as an official 3D Slicer extension: the project is still in development, so it does not appear in the Extensions Manager. For now, install it manually (repository folder + module path), as below.

Ce qu’il vous faut

  • 3D Slicer, version récente.
  • Git et GitHub CLI (gh), accessibles depuis le terminal.
  • Un compte GitHub.
  • Le paquet Python xxhash dans le Python de Slicer.

Installer Git et GitHub CLI

  1. Installez Git : git-scm.com/downloads.
  2. Installez GitHub CLI : cli.github.com.
  3. Vérifiez dans un terminal :
git --version
gh --version

Installer le module (la vidéo ci-dessus montre ces étapes)

  1. Depuis le dépôt GitHub du projet (bouton Code du site) : Code → Download ZIP, puis décompressez l’archive.
  2. Dans Slicer, ouvrez Edit → Application Settings → Modules.
  3. Dans Additional module paths, cliquez sur le bouton pour ajouter un chemin et sélectionnez le dossier CollaborativeVersioning.
  4. Installez xxhash : console Python (View → Python Console), puis : 
    slicer.util.pip_install("xxhash")
  5. Redémarrez Slicer.
  6. Ouvrez le module : liste des modules → Informatics → BRAVIS.

03Connexion GitHubGitHub sign-in

La connexion passe par la GitHub CLI et un code à usage unique, sans jamais saisir votre mot de passe dans Slicer. Sign-in goes through the GitHub CLI and a one-time code, without ever typing your password into Slicer.

Compte déjà présent sur cet ordinateur

Si la GitHub CLI est déjà connectée, une fenêtre GitHub account s’affiche d’abord : This computer is already signed in to GitHub as …

  • Continue — reprendre ce compte (sans rouvrir le navigateur).
  • Switch account — se déconnecter puis refaire le parcours web ci-dessous.
  • Cancel — annuler.

Première connexion (ou Switch account)

  1. Cliquez sur Connect with GitHub. Une fenêtre résume les étapes : cliquez sur Open sign-in window.
  2. Dans la fenêtre de connexion qui s’ouvre, répondez Yes si on vous demande d’authentifier Git avec vos identifiants GitHub. Au besoin, connectez-vous à GitHub dans le navigateur.
  3. Un code à usage unique s’affiche (il est aussi copié dans le presse-papiers). Appuyez sur Entrée : le navigateur s’ouvre sur github.com/login/device.
  4. Collez le code et autorisez l’accès.
  5. Revenez dans Slicer et cliquez sur I have signed in. Le statut affiche votre compte, et le bouton devient Disconnect.

Mode local (hors ligne)

Si GitHub est injoignable après Continue, la fenêtre Cannot reach GitHub propose :

  • Try again — retenter la connexion ;
  • Local mode — travailler hors ligne avec les projets déjà présents sur cet ordinateur (Open, Save) ; Share, People (ajout), Assign, messages projet et notifications distantes restent indisponibles ;
  • Cancel — annuler.

En mode local, le statut ressemble à Not connected — … (local mode). Le bouton reste Connect with GitHub pour revenir en ligne plus tard.

Se déconnecter

Disconnect → Sign out. La prochaine connexion redemandera de se connecter dans le navigateur. C’est utile pour changer de compte ou sur un ordinateur partagé.

🔐

Certaines actions, comme supprimer un projet sur GitHub, demandent une autorisation GitHub supplémentaire. Une fenêtre GitHub permission vous guide ; terminez dans le navigateur puis cliquez sur I have authorized.

Account already on this computer

If the GitHub CLI is already signed in, a GitHub account window appears first: This computer is already signed in to GitHub as …

  • Continue — keep that account (no browser flow).
  • Switch account — sign out, then follow the web flow below.
  • Cancel — cancel.

First sign-in (or Switch account)

  1. Click Connect with GitHub. A window sums up the steps: click Open sign-in window.
  2. In the sign-in window that opens, answer Yes if asked to authenticate Git with your GitHub credentials. If needed, sign in to GitHub in the browser.
  3. A one-time code is shown (it is also copied to the clipboard). Press Enter: the browser opens github.com/login/device.
  4. Paste the code and authorize.
  5. Back in Slicer, click I have signed in. The status shows your account and the button becomes Disconnect.

Local mode (offline)

If GitHub is unreachable after Continue, the Cannot reach GitHub window offers:

  • Try again — retry the connection;
  • Local mode — work offline with projects already on this computer (Open, Save); Share, People (add), Assign, project messages and remote notifications stay unavailable;
  • Cancel — cancel.

In local mode, the status looks like Not connected — … (local mode). The button stays Connect with GitHub so you can go back online later.

Signing out

Disconnect → Sign out. The next connection will ask you to sign in again in the browser. Useful to switch account or on a shared computer.

🔐

Some actions, such as deleting a project on GitHub, need an extra GitHub permission. A GitHub permission window guides you; finish in the browser, then click I have authorized.

04Créer ou ouvrir un projetCreate or open a project

Un projet BRAVIS est un dépôt GitHub privé, plus une copie locale sur chaque ordinateur. A BRAVIS project is a private GitHub repository, plus a local copy on each computer.

Créer

Avant de créer : choisissez un 3D Volume et une Ontology map. Sans eux, Create reste grisé (Create needs: 3D Volume, Ontology map.). La Segmentation est optionnelle : si elle manque, BRAVIS en crée une vide aux dimensions du volume.

  1. Cliquez sur Create.
  2. Dans New project, saisissez un Project name et, si vous voulez, une Description courte.
  3. Validez avec Create. Le dépôt privé est créé sur GitHub, avec sa copie locale. Vous en êtes l’owner.
✅

Chaque segment doit s’appeler Segment_ID (ex. Segment_64), sans doublon d’ID. Sinon Create et Save sont refusés.

Ouvrir

  1. Choisissez le projet dans la liste Project.
  2. Cliquez sur Open. À la première ouverture, la copie locale est clonée depuis GitHub. Les fois suivantes, Open charge uniquement la copie déjà présente sur cet ordinateur — sans fetch silencieux.
💡

Pour récupérer ce que les autres ont partagé, utilisez la cloche → Compare with shared (pas Open). Un projet déjà ouvert ne peut pas être rouvert (This project is already open.). Un projet suivi de (not on GitHub) est une copie locale dont le dépôt GitHub n’existe pas (supprimé ou jamais publié).

Les projets auxquels vous êtes invité apparaissent après avoir accepté l’invitation (voir People).

Create

Before creating: pick a 3D Volume and an Ontology map. Without them, Create stays disabled (Create needs: 3D Volume, Ontology map.). Segmentation is optional: if missing, BRAVIS creates an empty one matching the volume.

  1. Click Create.
  2. In New project, enter a Project name and, optionally, a short Description.
  3. Confirm with Create. The private repository is created on GitHub, with its local copy. You are its owner.
✅

Every segment must be named Segment_ID (e.g. Segment_64), with no duplicate IDs. Otherwise Create and Save are refused.

Open

  1. Pick the project in the Project list.
  2. Click Open. On the first open, the local copy is cloned from GitHub. Later opens only load the copy already on this computer — no silent fetch.
💡

To pick up what others shared, use the bell → Compare with shared (not Open). A project that is already open cannot be reopened (This project is already open.). A project followed by (not on GitHub) is a local copy whose GitHub repository does not exist (deleted or never published).

Projects you are invited to appear once you accept the invitation (see People).

05Volume, segmentation et ontologieVolume, segmentation and ontology

BRAVIS versionne la segmentation d’un volume. Indiquez-lui quels éléments de la scène Slicer suivre. BRAVIS versions the segmentation of a volume. Tell it which items of the Slicer scene to track.

  1. Chargez votre volume dans Slicer comme d’habitude (glisser-déposer ou Add Data).
  2. 3D Volume : choisissez ce volume (obligatoire pour Create et Save).
  3. Segmentation : choisissez la segmentation (ou une labelmap) à versionner. Pour Create, elle est optionnelle : une segmentation vide est créée si besoin.
  4. Ontology map (JSON) : choisissez Allen Mouse Brain Atlas, Allen Human Brain Atlas, ou chargez votre propre fichier via ⚙ → Load JSON…. Le premier choix est None ; un projet ouvert peut aussi afficher l’ontologie du dépôt. Obligatoire pour Create et Save.
  5. Annotez avec le Segment Editor de Slicer, puis enregistrez avec Save.
✅

Nommage des segments : chaque segment doit s’appeler Segment_ID (par exemple Segment_64), sans doublon. C’est obligatoire pour Create et Save, et c’est ce qui permet à l’arbre anatomique de savoir ce qui est annoté.

  1. Load your volume in Slicer as usual (drag and drop or Add Data).
  2. 3D Volume: pick that volume (required for Create and Save).
  3. Segmentation: pick the segmentation (or a labelmap) to version. For Create it is optional: an empty segmentation is created if needed.
  4. Ontology map (JSON): pick Allen Mouse Brain Atlas, Allen Human Brain Atlas, or load your own file via ⚙ → Load JSON…. The first choice is None; an open project may also show the repo ontology. Required for Create and Save.
  5. Annotate with Slicer’s Segment Editor, then record with Save.
✅

Segment naming: every segment must be named Segment_ID (for example Segment_64), with no duplicates. Required for Create and Save, and that is how the anatomy tree knows what is annotated.

06Ontologies et éditeurOntologies & editor

Une ontologie décrit la hiérarchie des structures anatomiques. Deux atlas Allen sont fournis ; vous pouvez aussi créer ou modifier la vôtre. An ontology describes the hierarchy of anatomical structures. Two Allen atlases are included; you can also create or edit your own.

Le menu ⚙

  • Help… : la référence du format JSON.
  • Load JSON… : charger une ontologie depuis un fichier.
  • Edit… : ouvrir l’Ontology editor.
  • Export JSON… : enregistrer l’ontologie actuelle dans un fichier.

L’éditeur

En haut : Atlas name (titre de l’ontologie) et Levels shown (profondeur affichée dans l’arbre ; 1 = racine seule). Sélectionnez une structure puis utilisez Add root, Add child, Rename ou Remove. Apply valide les changements, Cancel les abandonne.

Format JSON

Un objet racine avec atlas_name (titre) et tree (nœud racine). Chaque nœud a un id unique, un symbol (abréviation), un name et une liste children (vide pour une feuille).

The ⚙ menu

  • Help…: the JSON format reference.
  • Load JSON…: load an ontology from a file.
  • Edit…: open the Ontology editor.
  • Export JSON…: save the current ontology to a file.

The editor

At the top: Atlas name (ontology title) and Levels shown (tree depth to display; 1 = root only). Select a structure, then use Add root, Add child, Rename or Remove. Apply keeps the changes, Cancel drops them.

JSON format

A root object with atlas_name (title) and tree (root node). Each node has a unique id, a symbol (abbreviation), a name and a children list (empty for a leaf).

{
  "atlas_name": "My brain atlas",
  "tree": {
    "id": "997", "symbol": "root", "name": "Brain",
    "children": [
      { "id": "8",  "symbol": "grey", "name": "Basic cell groups and regions",
        "children": [
          { "id": "567", "symbol": "CH", "name": "Cerebrum", "children": [] }
        ] }
    ]
  }
}

07Arbre anatomiqueAnatomy tree

View anatomy tree affiche l’ontologie sous forme d’arbre et montre, structure par structure, ce qui est déjà annoté. View anatomy tree shows the ontology as a tree and, structure by structure, what is already annotated.

Naviguer

  • Double-clic : les détails de la structure (Structure details).
  • Collapse all : revenir au niveau racine. Molette pour zoomer, glisser pour se déplacer.
  • Chaque niveau de profondeur a sa couleur de bordure.

Gauche ○Pas d’annotation pour cette structure.
Droite ●Parents seulement : toutes les structures de plus bas niveau en dessous sont annotées.

Navigating

  • Click a parent: expand or collapse its children.
  • Double-click: the structure’s details (Structure details).
  • Collapse all: back to the root level. Wheel to zoom, drag to pan.
  • Each depth level has its own border color.

MarkMeaning

09Switch version

Charger n’importe quelle version dans Slicer pour la consulter ou repartir de là. Load any version in Slicer to look at it or start again from there.

  1. Dans le Version tree, cliquez sur le nœud voulu.
  2. Confirmez avec Switch version. La segmentation de cette version est reconstruite et chargée dans les vues.
⚠️

Faites Save avant de changer de version si vous voulez garder votre travail en cours.

Sur un nœud 🔒, Switch reste possible pour regarder. Pour travailler, revenez sur la branche de votre tâche (nœuds sans cadenas).

  1. In the Version tree, click the node you want.
  2. Confirm with Switch version. That version’s segmentation is rebuilt and loaded in the views.
⚠️

Save before switching if you want to keep your current work.

On a 🔒 node, Switch still works to look. To work, go back to your task branch (nodes without a padlock).

11Branches et sous-branchesBranches & sub-branches

Une branche permet d’essayer une annotation sans toucher à la ligne principale. On la crée depuis Save → Create a branch. A branch lets you try an annotation without touching the main line. Create one from Save → Create a branch.

  • Depuis main, le nom reste simple : sos, lol…
  • Depuis une autre branche, le nom devient parent/enfant : depuis sos → sos/ok ; depuis sos/ok → sos/ok/yoi.
  • Vous ne tapez que le dernier morceau, sans / ni +. Le parent est ajouté automatiquement.

Ensuite : Save sur cette sous-branche, puis Share pour la publier, et Merge pour la ramener dans son parent.

  • From main, the name stays flat: sos, lol…
  • From another branch, the name becomes parent/child: from sos → sos/ok; from sos/ok → sos/ok/yoi.
  • You only type the last part, without / or +. The parent is added automatically.

Then: Save on that sub-branch, Share to publish it, and Merge to bring it back into its parent.

12Share

Share publie sur le projet partagé les versions locales de la branche courante. Les pointillés deviennent pleins. Share publishes the local versions of the current branch to the shared project. Dashed nodes turn solid.

  1. Cliquez sur Share. Une confirmation indique la branche et la version jusqu’où publier (Up to).
  2. BRAVIS publie la branche jusqu’à ce bout, avec les versions parentes non partagées dont l’historique a besoin. Les autres branches locales ne bougent pas.
  3. Avant d’envoyer, l’outil vérifie le projet partagé. S’il contient des versions que vous n’avez pas, ou des bouts divergents, Share est refusé : passez par Compare with shared, puis réessayez.

Share est aussi bloqué si…

  • il n’y a rien de nouveau à partager ;
  • vous êtes junior hors de votre zone autorisée (cadenas) ;
  • une review 🔵 est ouverte sur cette branche de tâche : Share est en pause jusqu’à Accept ou Decline.
💡

Pour une sous-branche, Share publie aussi ce qu’il faut des branches parentes pour que le graphe distant reste cohérent. Rien à cocher.

  1. Click Share. A confirmation shows the branch and the version to publish up to (Up to).
  2. BRAVIS publishes the branch up to that tip, with any unshared parent versions the history needs. Other local branches do not move.
  3. Before sending, the tool checks the shared project. If it holds versions you do not have, or diverging tips, Share is refused: go through Compare with shared, then retry.

Share is also blocked when…

  • there is nothing new to share;
  • you are a junior outside your allowed area (padlock);
  • a 🔵 review is open on that task branch: Share is paused until Accept or Decline.
💡

For a sub-branch, Share also publishes what is needed from the parent branches so the remote graph stays consistent. Nothing to tick.

13Compare with shared

Quand le projet partagé a avancé sans vous, comparez votre arbre local avec lui, choisissez quoi faire, puis validez. When the shared project moved on without you, compare your local tree with it, choose what to do, then validate.

Quand l’utiliser

  • La cloche affiche ⚠ : Local project is not aligned with the remote copy.
  • Share ou Merge est refusé parce que le projet distant est en avance.

La fenêtre

14Merge & Compare

Fusionner une branche dans une autre, après avoir comparé les deux versions côte à côte dans 6 vues synchronisées. Merge one branch into another, after comparing both versions side by side in 6 synchronized views.

Lancer un merge

  1. Ouvrez les Version details (double-clic) du bout de la branche à fusionner. Le bouton Merge n’apparaît que si le merge est permis (voir les règles plus bas).
  2. Confirmez avec Compare and Merge. Slicer passe en disposition de comparaison.

La disposition Compare and Merge

  • En haut, les deux vues 3D ; en bas, pour chaque version, les vues Axial, Sagittal et Coronal. La version cible est à gauche en 3D et en haut en 2D ; la version source à droite en 3D et en bas en 2D.
  • La liste SEGMENTS indique pour chaque segment s’il existe dans les deux versions. ◀ Prev et Next ▶ passent de l’un à l’autre.
  • Show all segments : tous les segments avec leurs vraies couleurs. Décoché : un segment à la fois, vert pour la cible et rouge pour la source.
  • Show 3D : construire les surfaces 3D (désactivé par défaut, plus rapide).
  • Show cube diffs : entourer les cubes modifiés sur les vues 2D.

Starting a merge

  1. Open the Version details (double-click) of the tip of the branch to merge. The Merge button only shows when the merge is allowed (see the rules below).
  2. Confirm with Compare and Merge. Slicer switches to the compare layout.

The Compare and Merge layout

  • Both 3D views on top; below, for each version, the Axial, Sagittal and Coronal views. The target version is left in 3D and upper in 2D; the source version is right in 3D and lower in 2D.
  • The SEGMENTS list shows whether each segment exists in both versions. ◀ Prev and Next ▶ step through them.
  • Show all segments: every segment in its real colors. Unchecked: one segment at a time, green for target and red for source.
  • Show 3D: build 3D surfaces (off by default, faster).

  3. Apply merge construit la nouvelle version à partir des cubes choisis. Quit quitte sans fusionner et rétablit l’affichage.

21Delete

Deux suppressions très différentes : une version locale, ou le projet entier. Two very different deletions: a local version, or the whole project.

Une version locale

Sur une version en pointillés, Version details → Delete retire seulement cette version locale. Le projet partagé n’est pas touché. Une version déjà partagée ne peut pas être supprimée ainsi.

Le projet

Le bouton Delete du panneau ouvre Delete project. Selon votre rôle :

  • Owner (en ligne) : This computer only (garde GitHub) ou GitHub and this computer (supprime pour tout le monde ; fenêtre GitHub permission possible).
  • Non-owner, mode local, ou projet (not on GitHub) : suppression de la copie locale uniquement.
⛔

GitHub and this computer est irréversible : toute l’équipe perd l’accès au projet partagé. Les copies locales restantes apparaissent alors avec la mention (not on GitHub).

A local version

On a dashed version, Version details → Delete removes only that local version. The shared project is untouched. An already shared version cannot be deleted this way.

The project

The panel’s Delete button opens Delete project. Depending on your role:

  • Owner (online): This computer only (keeps GitHub) or GitHub and this computer (removes it for everyone; GitHub permission window may appear).
  • Non-owner, local mode, or (not on GitHub) project: remove the local copy only.
⛔

GitHub and this computer is irreversible: the whole team loses access to the shared project. Remaining local copies then show (not on GitHub).

23Stockage des segmentationsSegmentation storage

Pour aller plus loin : comment BRAVIS garde un historique léger, même avec de gros volumes. Going further: how BRAVIS keeps a lightweight history, even with large volumes.

La segmentation est découpée en cubes de 64×64×64 voxels. Chaque cube est compressé (zlib) et nommé par l’empreinte xxHash64 de son contenu. Un cube identique n’est donc stocké qu’une fois : un Save n’ajoute au dépôt que les cubes qui ont changé.

The segmentation is split into 64×64×64-voxel cubes. Each cube is compressed (zlib) and named after the xxHash64 fingerprint of its content. An identical cube is stored only once: a Save only adds the cubes that changed.

24Limites actuellesCurrent limitations

Pour ne pas chercher en vain. So you don’t look for them in vain.

  • Pas encore de « Share my workspace » ni de suivi en temps réel entre collègues.
  • En mode local, Share, People (ajout), Assign, messages projet et notifications distantes sont indisponibles.
  • La version de départ d’une tâche doit être sur main ; les départs depuis d’autres branches viendront plus tard.
  • Les détails du Version tree peuvent être un peu plus lents sur certaines sous-branches (calculs de Merge). Une amélioration est prévue.
  • Les collègues ne sont pas mis à jour automatiquement : chacun fait Compare / Update.

Une question ? Consultez la FAQ et le dépannage.

  • No “Share my workspace” or real-time awareness between colleagues yet.
  • In local mode, Share, People (add), Assign, project messages and remote notifications are unavailable.
  • A task start version must be on main; starts from other branches will come later.
  • Version tree details can be a little slower on some sub-branches (Merge computations). An improvement is planned.
  • Colleagues are not updated automatically: each one runs Compare / Update.
